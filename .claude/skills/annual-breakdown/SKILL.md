# /annual-breakdown

`reports/<name>/report_data.js` を暦年(決済年・UTC)ごとに分解し、トレード数・PF・勝率・純益・
年内最大DDを表にする。あわせて2つの機械警告を出す:

- **(a) 単年集中**: いずれかの暦年の純益寄与が全期間純益の50%を超える
- **(b) 年次フロア割れ**: いずれかの暦年で PF < 0.9

## 実行

```
python tools/annual_breakdown.py reports/<report_dir> [--json]
```

Windows のコンソール文字化けを避けるため、直接実行時は `PYTHONIOENCODING=utf-8` を付けるか、
このツールは内部で `sys.stdout.reconfigure(encoding="utf-8")` 済みなのでそのままでも通常表示される。

終了コード: 警告が1件でもあれば `1`、無ければ `0`。

## 使うタイミング(必須)

- 新パラメータ・新フィルタのバックテスト結果を評価するとき(採否の判断材料は全期間PFではなく本ツールの
  出力にする)。
- 新手法・新変種(例: narrow_focus_mtf)を登録し実測したとき。
- `/sweep` の各候補構成を評価するとき(過剰適合の疑いがある候補は採用推奨に含めない)。

## 既知の参照値(このツールの健全性チェック用)

- `reports/smc_bos_full`: (a)(b) 両方発火する(2022年PF0.801の赤字年+2026年が純益の約60%)。
  → smc_bos がライブ凍結(年次フロア不合格)と判定された根拠そのもの。
- `reports/atr_trend_scalp_full`: 警告なし(全暦年PF>1.35)。→ ポートフォリオ最良エッジの根拠。
- `reports/rule_depth50`(depth50): (b) が 2021年(PF0.599)で発火する。既知の追加所見であり、
  depth50 のコード変更は必要ない(ビット一致の絶対制約下では改善不可。改善するなら新変種登録)。

## 注意

- 本ツールは `report_data.js` の**読み取りのみ**。トレード判定コードには一切触れない。
- 採否基準(閾値50%・PF0.9)は事前宣言済み。実験結果を見てから閾値を変更しない。
