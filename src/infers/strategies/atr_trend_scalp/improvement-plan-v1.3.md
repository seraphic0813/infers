# atr_trend_scalp v1.3 パラメータ探索計画(2026-11-14 起案・承認待ち)

v1.2(現行デモ構成)を上回るパラメータを、過剰適合を避けながら探す。
本書は**実験前の事前宣言**であり、結果を見てから基準を変更しない(CLAUDE.md 定石6)。

## 0. 前提の整理

- **検証の重さは手法ごとに違う。** atr_trend_scalp のバックテストは `tools/sweep.py` で
  **1構成あたり約4〜5秒**(5年分、2026-11-14 実測)。20分以上かかるのは depth50
  (narrow_focus の回帰確認)の方。
- **depth50 はパラメータ探索中は回さない。** 探索は atr の provider 引数を差し替えるだけで
  コードを変えないため、depth50 の結果は原理的に変わらない。depth50(`/bit-check`)は
  **最後に既定値をコードへ反映してコミットする時に1回だけ**回す。
- **ユーザー提案の「まず短い期間で検証 → 良ければ本番」は、速度のためではなく
  過剰適合を防ぐ「期間の分割」として採用する(§2)。**

## 1. ベースライン(v1.2・現コードで再測定)

a312282(建玉ミラー精緻化)以降、atr の確定値が測り直されていなかったため、
ここを起点として測り直す。数値は `tools/sweep.py`(固定ロット)。

| 期間 | 用途 | v1.2 の値 |
|---|---|---|
| 全期間 2021-06-14〜2026-11-13 | 年次分解 | 2,293件 / PF 1.525384103 / DD 11,117 |
| 調整用 2021-06-14〜2026-06-11 | 探索・比較 | ステージ0で確定 |
| 未使用期間 2026-06-12〜2026-11-13 | 最終確認のみ | ステージ0で確定(CLIでは152件 / PF 1.077) |

## 2. 期間の分割(覗き見の制限)

- **調整用期間(〜2026-06-11)**: 探索で何度でも使う。v1.1/v1.2 の調整でも使った期間。
- **未使用期間(2026-06-12〜11-13)**: v1.2 確定後の新データで、**まだ誰も調整に使っていない
  唯一の期間**。探索中は見ない。**最終候補(最大3構成)にだけ1回ずつ**当てる。
  何度も見て選ぶと、この期間も調整用になってしまうため。

## 3. 採用基準(すべて満たすこと・事前宣言)

| # | 基準 | 目的 |
|---|---|---|
| a | 調整用期間の PF ≥ ベースライン + 0.03 | 誤差でない改善 |
| b | 全期間で、全暦年の PF > 1.30、単年の純益寄与 ≤ 50% | 年次分解(定石6) |
| c | 全期間の最大DD ≤ ベースライン × 1.10 | リスクを増やして稼いでいない |
| d | 全期間のトレード数 ≥ ベースライン × 0.70 | 件数を絞りすぎて偶然に頼っていない |
| e | 隣の値(±1刻み)も基準aの半分(+0.015)以上を満たし、振動警告が無い | 「その値だけ当たり」ではない |
| f | 未使用期間の PF ≥ ベースラインの未使用期間 PF | 新しい相場でも悪化しない |
| g | `--slippage-ticks 1` での全期間 PF ≥ ベースラインの同条件 PF | 約定のずれに弱くない |

一つでも満たさなければ不採用として記録する。基準は緩めない。

時間単位の境界なので影響なし)。

1周あたり約50構成(約5分)。

## 5. 手順

0. **ベースライン再測定**: 調整用期間・未使用期間・スリッページ1ティックで v1.2 を測り、§1 の空欄を確定。
1. **ステージA・B(OFAT)**: 調整用期間で探索 → 基準a・e(とd)で候補を絞る。
2. **ステージC(グリッド)**: 候補の組合せを調整用期間で探索。
3. **全期間チェック**: 上位候補に基準b・c・d・g を適用。
4. **最終確認**: 残った最大3構成だけ未使用期間に当てる(基準f)。
5. **確定**: 合格構成を CLI(`--risk-pct 0.0003`)で全期間レポート化し、年次分解。
   既定値(またはプリセット `atr_trend_scalp_v13`)としてコードに反映し、
   `/bit-check`(pytest + depth50)を**1回だけ**実行 → spec.md に記録 → PR。

## 6. 終了条件

- 合格構成が見つかった時点で §5-5 へ進む。
- **見つからない場合**: ステージC を周辺に広げて最大3周(約150構成)まで続ける。
  それでも無ければ「v1.2 を上回る構成は無かった」と記録して終了し、基準は緩めない
  (緩めて採用すると、smc_bos で3回起きた過剰適合を繰り返すため)。
- 試行数が増えるほど「偶然良く見える構成」も増えるため、§2 の未使用期間の
  覗き見回数は全体で最大3回に固定する。

## 7. 影響範囲

- 探索中はトレード判定コードを変更しない(`tools/sweep.py` の引数指定のみ)。
- 稼働中の atr デモ(v1.2)には影響しない。採用構成をデモへ反映するかは確定後に判断する。
