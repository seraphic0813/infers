## Executive Summary

**全体評価**: プラットフォーム化(6層+registry+ExecutionModel 抽象)は完成度が高く、depth50 ビット一致を完了ゲートとする移行規律も機能している。再設計は不要。主要な非効率は3つ:

1. **不使用の LLM 判定層が全手法のホットパスに残存** — 非NF手法はゲート通過のためのプレースホルダ特徴量を捏造している(死んだ複雑さ)。
2. **検証インフラ(年次分解・ビット一致確認)が手作業** — 全実験の律速であり、過剰適合検出(3回実証済みの教訓)の再現性が属人的。
3. **全アクティブ手法が XAUUSD に集中** — 口座は3つに分離されているが原資産は1つ。相関・合成DDが未測定。

**最高ROI上位**: ① 検証自動化(/bit-check+年次分解)② atr_trend_scalp のデリスク(スリッページ・ストレス+デモ約定検証)③ LLM層の隔離撤去 ④ 口座横断リスク集約 ⑤ smc_bos の役割確定(→年次フロア不合格でライブ凍結が確定。作業プラン D3)。

## 1. 手法個別の分析

### 1.1 depth50 / narrow_focus(v1.0 基準実装)

- **実測**: PF 1.489・624トレード・DD $326・勝率53.4%・双方向黒字(reports/rule_depth50)。
- **構造課題**: ①売り84%偏重(3段カスケード=プラン生成・約定率・ランナー化。マクロD1方向が100%支配)、②手法はマルチTF(判定H1・90SMA=日足)想定だが実装は M5 単一足 — **最重要の戦略課題**。
- **掘り尽くした領域(全て実測済み・不採用)**: macro_k 較正(1.0/1.25 で単調悪化、k=1.5 最良)、深さ緩和・失効リカバリー(買い増えず)、M15 化(PF0.778 に劣化)、建値距離拡大(全案赤字)、可変ロット(優位性なし)。**パラメータ空間に残余なし。残る改善は構造のみ**。
- **提案**: (a) マルチTF 変種 `narrow_focus_mtf` を depth50 不変のまま**新規登録**して実測(作業プラン T16。採否基準は事前宣言: 全暦年PF>1.2+買い側黒字)。(b) depth50 内のチューニングは明示的に凍結し、上げ相場の捕捉は他手法に役割分担。

### 1.2 smc_bos(XAUUSD M30)

- **実測**: 全期間 PF 1.456・197トレード・DD $912・勝率32%。ただし**年次分解で 2022=PF0.801(−$357)赤字、2026年6トレードが純益の60%**。頻度レバー(lookback/buffer/EMA)は袋小路と確定済み。rr_target 感度は非単調振動=過剰適合シグナルで 3.0 据え置き済み。
- **判定**: 年次フロア(全暦年PF≥0.9)不合格 → **ライブ凍結**(ユーザー決定。作業プラン D3)。ForexFloor 出典 PF2.55 の再現追求は打ち切り。
- **再開研究(優先度最低)**: 出口の質(trailing)・ATRレジームフィルタで平常年PF≥0.9 に到達した場合のみ再判定。

### 1.3 atr_trend_scalp(XAUUSD M5・3口座目)

- **実測(v1.1)**: PF 1.550・2,963トレード・DD $71・勝率59.9%・**全暦年 PF>1.35**(最弱2022=1.354)。ポートフォリオ中唯一「全レジームで安定」= 現在の最良エッジ。建値化+トレールの分散的出口が明確にプラス寄与(smc_bos の at_1r とは対照的)。
- **最大リスク**: `trail_atr_mult=0.15`(≈6ティック)の約定現実性が未検証。「バックテストの利益がトレール極小幅の理想約定に依存」の可能性。→ スリッページ・ストレステスト(T7、事前宣言基準: 2ティック注入でPF<1.2なら幻)+デモ乖離実測(T8)を実口座昇格の関門にする。
- スワップ表記の疑義は検証済みで**矛盾なし**(モデル有効・保有中央値10分で発生額0。作業プラン D4)。

執行抽象の実証用でありエッジを主張しない。**運用非対象と明記**して残置(結合テストのフィクスチャとして有用・197行)。退役させない。

## 2. シンプル化 — AI層の解剖(本レポートの中核的発見)

「AI層」は一枚岩ではなく3部分からなり、撤去可否が異なる:

| 部分 | 実体 | 判定 |
|---|---|---|
| **(a) LLM 実呼び出し系** | `AnthropicLlmClient`・`ai/batch.py`・main.py の judge/submit/fetch/ingest モード・2パス機構 | **完全に不使用 → 撤去(T6)** |
| **(b) 決定論ルールゲート** | `ai/rule_judge.py`+`VerdictCache` | **撤去不可**。depth50 の稼働経路そのもので、完了ゲートの再現値にゲート統計(CACHE GO3124・NO_GO1034)を含む。実質「NF手法のエントリー判定の最終段」 |
| **(c) ゲートの全手法強制** | `TradingLoop` が全プランに `gateway.judge(..., cluster_score, ambiguity)` を強制。非NF手法は NF 語彙を中立値で捏造 | **手法宣言化で縮退(T15)**。`StrategySpec.gate`(既定 None=ゲートを呼ばない)。「一般化」ではなく「縮退」で phase2 の積み残しを解消 |

**ビット一致の定義は「強い一致」(ゲート統計込み)を採用**(ユーザー決定 D1)。理由: 弱い一致(トレード列のみ)では「経路を変えたが5年データではたまたま同じ」変更が素通りし、ライブの未知データで初めて食い違うリスクがある。ゲート統計は「出力が同じ」ではなく「機械に触っていない」ことのトリップワイヤー。

**その他**: `analysis/`(dow.py・support_resistance.py)は NF 固有につき narrow_focus へ移設(T14)。旧実験レポート20+個は archive/ へ。`TfResampler`/`MacroResampler` の重複は2手法目の利用確定まで放置(L1昇格の定石どおり)。

## 3. 目標アーキテクチャ

現行6層は健全。**層の再編はせず「引き算」のみ**:

```
L4 frontend   report_html(ReportSpec駆動) / dashboard(+口座横断集約★)
L3 backtest   engine / slicing / sweep★(年次分解内蔵)
L5 live       mt5_adapter / mt5_feed(LLM関連は消滅★)
L2 strategies registry(+gate宣言★)
              narrow_focus(dow/SR/rule_gateを吸収★)=depth50 /
              market_tpsl(実証用) / smc_bos(凍結) / atr_trend_scalp
L1 indicators SMA/EMA/RSI/ATR(現状維持)
L0 core       loop(gateway強制が消えExecutionModel抽象のみ依存が完成★)
              models / risk / journal
★=本プランの変更点
```

**やらないこと(意図的)**: マイクロサービス化・DB導入・非同期化・複数手法の1プロセス同時稼働(1手法/1プロセス+別ターミナルは障害分離として優秀)。

## 5. ポートフォリオ分析

| 手法 | エッジ源泉 | レジーム | 年次安定性 | 役割(確定) |
|---|---|---|---|---|
| depth50 | 調整局面の戻り売り(逆張り+構造防御) | 下落・調整 | 中 | コア(防御的) |
| atr_trend_scalp | 高ボラ・トレンド日の順張りスキャル | トレンド・拡大ボラ | **高** | コア(攻撃的)— T7/T8 通過が実口座条件 |

- **集約リスク**: 全アクティブ手法が XAUUSD。金の急変日に複数口座が同時DDし得るが相関未測定 → 相関行列+コンボDD算出(T11)、口座横断モニタ(T12。表示のみ・自動介入なし)。
- **配分枠組み**: 伸ばす=全暦年フロア+デモ乖離合格(atr候補)/維持=双方向黒字+DD予算内(depth50)/凍結=平常年フロア未達(smc_bos・確定)/退役=2年連続未達またはライブ乖離大。
- **資産分散(BTCUSD/USDJPY)**: 将来想定あり・**保留**(D5)。

## 6. 開発時 Agentic 化(トレード判断のホットパス非侵入)

- **Skill**: `/bit-check`(完了ゲートのワンコマンド化・最頻用)/`/annual-breakdown`(過剰適合の機械警告: 単年寄与>50%・暦年PF<0.9)/`/sweep`(ビット一致自己検証+年次分解強制+非単調検出時は採用推奨を出さない)。
- **サブエージェント**: 最適化→アナリスト→インバリアント・レビュアー(A-1〜15+B契約チェックリスト)→/bit-check の**直列**パイプライン(再現性優先で並列多重化しない)。採否基準の事後変更を禁じるプロンプトを持たせる(過剰適合の人間側対策)。

## 7. 代替案とトレードオフ(不採用の記録)

| 代替案 | 不採用理由 |
|---|---|
| AIゲートの手法非依存への一般化(phase2 フェーズ3課題の本筋) | LLM不使用が正式方針の今、「使わない機構を立派にする」投資。縮退(gate宣言化)が安く、宣言点が将来の再導入口を兼ねる |
| AI層の全面即時削除(gateway/cache/rule_judge ごと) | rule_judge+cache は depth50 の稼働経路。得るのは数百行、失うのは v1.0 の再現性 |
| depth50 本体のマルチTF化(改修) | ビット一致原則と正面衝突。新変種登録なら既存に触れず同じ検証ができる |
| 口座横断の自動キルスイッチ | プロセス独立・決定論・冪等の3原則に横断的自動介入は責任分界を複雑化。警告表示+人間判断+既存ラッチで足りる |
| 全手法共通のレジーム検知層 | 手法ごとの opt-in フィルタで同じ仮説を安く検証できる。共通層は2手法以上で有効と実証されてから(L1昇格の定石と同型) |

## 8. リソース考慮

- depth50 フル再現≈25分が /bit-check の律速(コミット前はフル必須を維持)。atr はインプロセス・スイープ1構成≈4秒で実験の主戦場。smc_bos は M30・5.9万本で軽量。
