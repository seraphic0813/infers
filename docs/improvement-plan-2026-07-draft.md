## Executive Summary

**全体評価**: プラットフォーム化(6層+registry+ExecutionModel 抽象)は既に完成度が高く、depth50 ビット
一致を完了ゲートにした段階的移行の運用規律も機能している。新規性のための再設計は不要。現在の主要な

集約が存在しない。

## 2. シンプル化の機会

### 2-1. AI/LLM 層の解剖 — 何が死んでいて何が生きているか

コードを読んだ結果、「AI層」は一枚岩ではなく**3つの独立した部分**からなる。撤去可否が異なる:

| 部分 | 実体 | 現状 | 判定 |
|---|---|---|---|
| **(a) LLM 実呼び出し系** | `AnthropicLlmClient`(gateway.py 内 ~50行)、`ai/batch.py`(149行)、main.py の `--mode judge --batch/--submit/--fetch/--ingest`、`CacheOnlyClient`、2パスバックテスト機構 | **完全に不使用**(正式方針でトレード判定に LLM 不使用) | **撤去候補(本命)** |
| **(b) 決定論ルールゲート** | `ai/rule_judge.py`(105行)+ `VerdictCache` | **depth50 の稼働経路そのもの**。完了ゲートの再現値に「CACHE GO3124・NO_GO1034」というゲート統計まで含まれる。$0・決定論で、実質 **Narrow Focus のエントリー判定の最終段** | **撤去不可。「AI層」から「NF手法の一部」へ再分類** |
| **(c) ゲート呼び出しの全手法強制** | `TradingLoop.on_candle` が全プランに `gateway.judge(plan.request, cluster_score=…, ambiguity=…)` を強制。非NF手法は `JudgementRequest`・`cluster_score`・`ambiguity` を**中立値で捏造**してゲートを通過している(smc_bos spec §5.1「ゲート tier 判定を通すためのプレースホルダ」) | パススルーで無害化されているが、**L0 に NF 語彙(cluster_score/ambiguity)が残存**する既知の境界違反。新手法追加のたびに捏造コードが増殖 | **簡素化候補(ゲートの手法宣言化)** |

### 2-2. 撤去手順(depth50 ビット一致を守る順序)

**ステップ1(安全・即実行可): LLM 実呼び出し系の隔離撤去**
- 削除: `ai/batch.py`、`AnthropicLlmClient`、main.py の judge/submit/fetch/ingest モード(main.py 651行の
うち相当量)、`--mode replay` は `backtest` の別名として温存または削除。`anthropic` を必須依存から外す
(将来再導入時は phase1 §7 の設計が文書として残る)。
- 温存: `Verdict`/`JudgementRequest`/`VerdictCache`/`EscalationPolicy`/`AiGateway` 本体/`rule_judge.py`/
`passthrough.py` — **depth50 の判定経路は1バイトも変えない**。
- 担保: pytest 全合格(`test_ai_backtest.py` は LLM 依存部分のみ削除・縮小)+ depth50 ビット完全一致
(ゲート統計含む)。
- スコア: 対象=全体 / 期待効果=中(保守負債減・「誤って課金経路を叩く」リスクの物理的排除)/
工数=中(2-3日)/ リスク=小 / **depth50影響=無**(判定経路不変を完了ゲートで担保可能)。

**ステップ2(中期): ゲートの手法宣言化**
- `StrategySpec` に `gate` 概念を追加(例: `gate="narrow_focus_rule"` / 既定 `None`)。`None` の手法は
**TradingLoop がゲートを呼ばない**(現在の「パススルーで GO を返させる」迂回より一段浅い)。NF/depth50 は
現行のルールゲートを宣言し、**呼び出し列・キャッシュキー・統計カウントが従来と完全一致**するよう配線。
- これにより: 非NF手法の `TradePlan` から `cluster_score`/`ambiguity`/`request` のプレースホルダ捏造が
消せる(将来の新手法テンプレートが簡潔になる)。L0 から NF 語彙が完全に消え、phase2 の積み残し
(§段階2.5 の既知課題)が「一般化」ではなく「縮退」で解消する。
- スコア: 対象=全体 / 期待効果=中 / 工数=中(3-5日)/ リスク=中(loop のホットパス変更)/
**depth50影響=要検証**(NF経路のゲート呼び出し列を不変に保つ設計が前提。ビット一致+ゲート統計一致を
完了ゲートに)。

**ステップ3(任意・低優先): `ai/` の改名・再配置**
- `rule_judge.py` を `strategies/narrow_focus/` 配下へ、gateway の残骸を `core/gate.py` 等へ。import 移動
のみだが、キャッシュキーに `MODELS[tier]`(モデルID文字列)が焼き込まれているため、**verdict_cache の
互換を壊さないこと**。効果は美観に近く、ステップ1・2完了後に気が向いたらでよい。工数=小 / リスク=小 /
depth50影響=無(import 移動のみなら)。

## 10. リソース考慮

- **バックテスト再実行**: depth50 全期間≈25分(メモリ既載)が `/bit-check` の律速。ビット一致検証は
Phase 1 では現状のまま受け入れ、必要なら `--last 1y` の短縮スモーク+週次フル、の2段構えにする
(ただし**コミット前の完了ゲートはフル必須**を維持)。atr_trend_scalp はインプロセス・スイープで
1構成≈4秒と軽く、実験の主戦場に適する。smc_bos は M30・5.9万本で軽量。
- **ストレージ**: Parquet 1ファイル正+レポートアーカイブ移動で現状十分。DuckDB 等の追加は不要。
- **LLMトークン**: 対象外(不使用)。再導入時のみ Batches+verdict_cache 前提で別途評価(phase1 §7 を
凍結仕様として保存)。

## 代替案とトレードオフ

- **AIゲートの手法非依存への一般化(phase2 が「フェーズ3課題」とした本筋)** → **不採用**。LLM 不使用が
正式方針の今、一般化は「使わない機構を立派にする」投資。縮退(手法宣言化+既定ゲートなし)の方が安く、
将来再導入するなら宣言点(`StrategySpec.gate`)がそのまま再導入の差し込み口になる。
- **AI層の全面即時削除(gateway/cache/rule_judge ごと)** → **不採用**。rule_judge+cache は depth50 の
稼働経路であり、完了ゲートの再現値にゲート統計が含まれる。得られるのは数百行の削減、失うのは v1.0
ベースラインの再現性 — 割に合わない。
- **depth50 本体のマルチTF化(改修)** → **不採用**。ビット一致原則と正面衝突。新変種登録なら同じ検証を
「既存に触れない」形で実施できる。プラットフォームの存在意義そのもの。
- **口座横断の自動キルスイッチ** → **不採用(警告のみ)**。プロセス独立・決定論・冪等の3原則に横断的な
自動介入を挟むと責任分界が複雑化する。低頻度事象への対応は人間判断+ラッチ式キル(既存)で足りる。
- **市場レジーム検知層の新設(全手法共通のボラ/トレンド分類器)** → **見送り**。魅力的だが、手法ごとの
opt-in フィルタ(SMC-3)で同じ仮説をまず安く検証できる。共通層はそれが2手法以上で有効と実証されてから
(L1昇格の定石と同じ判断)。
