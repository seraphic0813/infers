## v1.1 チューニングの要点(根幹不変・パラメータのみ)

PF1.5以上を目標に、**手法の根幹(4条件エントリー・50/50分割・建値化+トレール)は
一切変えず**、数値パラメータのみをスイープ探索で調整した(全探索は5年フルで実施し、
単年過剰適合を回避)。確定した変更は4つ:

| パラメータ | v1.0(旧) | v1.1(確定) | 効果 |
|---|---|---|---|
| `vol_mult`(出来高フィルタ) | 1.2 | **1.6** | エントリー品質↑(ダマシ排除) |
| `tp1_atr_mult`(第1利確) | 1.0 | **0.5** | 半利を早めに確保→勝率↑ |
| `tp2_atr_mult`(第2利確) | 2.0 | **3.0** | ランナーを伸ばす |
| `trail_atr_mult`(トレール幅) | 0.5 | **0.15** | 利益を細かく確保 |

その他(EMA期間・ATR・SL倍率1.0・retrace_lookback・session等)は不変。

## スリッページ・ストレステスト(2026-07-03、改善プラン T7)

**動機**: v1.1 の `trail_atr_mult=0.15`(≈6ティック)は約定現実性の下限に近い。
バックテストの優位性が「トレール極小幅の理想約定(SL価格ちょうどで滑りなく約定)」に
依存している可能性があり、これが幻なら実運用で成績が崩れる。これを$0で先行検証するため、
`SimBroker` に opt-in の逆方向スリッページ(`--slippage-ticks N`)を実装した。成行参入・
成行決済(TP)・保護SL/トレール決済の約定価格を不利方向へ N ティックずらす(指値約定は
指値契約のため対象外)。`N=0` は従来挙動と1ティックも変わらない(v1.1 黄金値を
ビット一致で再現して確認: trades=2963 / PF=1.550419248 / DD$71.02)。

**事前宣言した採否基準**: N=2(2ティックの逆スリッページ)で PF<1.2 なら trail=0.15 は
幻とみなし trail 再探索(T9)へ。PF≥1.2 ならデモ約定検証(T8)へ進む。

| slippage (ticks) | トレード数 | PF | 勝率 | 最大DD | 純益(5年) |
|---|---|---|---|---|---|
| **0**(=v1.1) | 2,963 | **1.550419248** | 59.91% | $71.02 | +$2,036.92 |
| 1 | 2,963 | 1.511797159 | 59.37% | $71.86 | +$1,918.40 |
| **2** | 2,963 | **1.474068065** | 59.13% | $72.78 | +$1,799.88 |
| 3 | 2,963 | 1.437234751 | 58.56% | $73.78 | +$1,681.36 |

**判定: 合格(PASS)。N=2 で PF=1.474 ≥ 1.2。** trail=0.15 の優位性は理想約定の幻では
ない。さらに N=3 でも PF=1.437 と 1.2 を大きく上回る。

**読み方**:
- **トレード数は全 N で 2,963 で不変**。スリッページは「どのトレードが成立するか」を
  変えず、約定価格のみを悪化させる。したがって劣化は純粋に約定コストであり、
  トレード選択の偶然に依存しない(健全なストレス応答)。
- PF・純益は N に対してほぼ線形に緩やかに劣化(PF は約 −0.038/tick、純益は約 −$118/tick)。
  破断的な崩壊は無い。純益劣化 ≈ 2,963トレード × 2約定(出入り)× 2step × N tick × $0.01 で
  説明できる(構造的に妥当)。
- 最大DDは $71→$74 とほぼ横ばい。
- **年次分解は N=0〜3 のすべてで警告ゼロ**(全暦年 PF>1.2。最弱は N=3 の2021年 PF1.238)。
  逆風下でも全レジームで黒字を維持する堅牢性を確認。

**次アクション**: T8(デモ運用でのトレール実約定検証)へ進む。デモで実測したジャーナル vs
SimBroker 期待値の乖離を本テストのスリッページ設定へフィードバックし、実測乖離を注入した
PF を実口座昇格の最終判定値とする。T9(trail再探索)は起動しない。

## デモ約定検証ツール + 実口座昇格基準(2026-07-03、改善プラン T8)

**ツール**: `tools/atr_demo_deviation.py`(単体テスト `tests/test_atr_demo_deviation.py` 8件)。
ライブ(デモ)のジャーナル(`work/journal/atr_trend_scalp_xauusd.jsonl`)から `SL_HIT` イベントの
実約定価格(`execution/mt5_adapter.py` の `poll_events()` が MT5 の実約定 `deal.price` を
そのまま記録)と、その時点で有効だった SL/トレール価格(直近の `MOVE_SL` の `new_sl`。無ければ
`MARKET_ENTRY` の `sl`)を突合し、乖離(ticks)の分布(中央値・p90)を算出する。

**トレール(TP1到達後=RUNNER状態)と初期SL(OPEN状態)を分けて集計する**(同一 position_id で
`TP_CLOSE(level=tp1)` が先行するかで判定)。T7 のフィードバック対象は前者(トレール関連)。

```
python tools/atr_demo_deviation.py work/journal/atr_trend_scalp_xauusd.jsonl
```

**実口座昇格基準(事前宣言)**:

1. **デモ運用期間**: 3口座目で最低2週間、連続稼働(途中停止・再起動を含めてよいが、
   合計稼働日数で2週間相当を満たすこと)。
2. **乖離実測**: 上記ツールで「トレール関連」SL_HIT の p90 乖離(ticks)を算出する。
3. **判定**:
   - p90 が T7 実測範囲(`--slippage-ticks` 0〜3)内 → T7 の該当N の実測PFをそのまま
     最終判定値とする(N=2/3 のいずれでも PF≥1.2 を確認済みのため、この場合は**昇格可**)。
   - p90 が3ティックを超過 → T7 スイープを p90 相当の N まで拡張再実行し、その N での
     PF が引き続き閾値(1.2)を上回るかで再判定する(下回れば実口座への昇格は見送り、
     trail 幅の再検討[T9相当]に戻る)。
4. **トレード数のサンプルサイズ**: `SL_HIT`件数(特にtrail区分)が極端に少ない場合
   (目安 n<20)、p90 は統計的に不安定なため、参考値に留め昇格の唯一の根拠にしない。
   デモ期間の延長を優先する。
5. **その他の安全条件**: デモ期間中にキルスイッチが誤作動・意図せず作動しないこと、
   ジャーナルとMT5建玉の乖離(リコンサイル不一致)が発生しないこと(発生した場合は
   原因究明を優先し、昇格判断を保留する)。

**現状**: デモ運用(2週間)は本ツール整備時点では未実施。本節はツールと基準の準備であり、
実測・最終判定はデモ運用完了後に追記する。
